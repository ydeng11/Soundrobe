## Current implementation

- `nativePrepared: true` selects a separate native bootstrap branch. It cannot carry trust paths, key bytes or activation. Fixture context construction rejects the selected native mode.
- Native process construction derives the fixed approval directory from the current account database, not HOME or child-selected configuration. A canonical owner-only directory holds bounded, same-owner, no-follow, single-link regular files.
- `prepared-bootstrap.json` binds version, the exact native-serialized plan hash, an independent verifier pin, text-pricing evidence and a lazy credential-file source. It contains no signing material. The established $5 estimate check remains unchanged.
- Exact owner IPC `approve_owner_file` reads only the fixed `prepared-approval.json`. Existing Journal verification consumes the signature once against scope, checkpoint, expiry and nonce. Missing/unsafe/invalid evidence retains terminal stop behavior. No signature is generated by this path.
- Public `testApproval` refuses native-prepared plans and hosted contexts without explicit fixture trust. Mock receipt validation refuses native-prepared results. The independent Python mock auditor already rejects the additional native plan field; no change to that auditor was necessary in this turn.
- Pinned HTTPS admission still returns `live_dispatch_disabled` before credential reads or model reservations, even after valid owner-file approval. No real bootstrap configuration or run approval file was provisioned.
