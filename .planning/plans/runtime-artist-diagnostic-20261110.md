## Independent-review corrections

The frozen authentic expectations above are unchanged. Independent reviews exposed and boundary tests reproduced additional requirements before final acceptance:

- Retain at most 2 MiB of an exact decoded response. Oversized metadata still parses normally; no receipt is retained or truncated.
- Validate candidate album-primary fields as well as track-facing artist fields against the same bound singleton entity.
- A lossy TrackData first-value projection is not complete original-primary evidence. Capture all recognized original FLAC primary comment tuples through the existing bounded layout validator and Lofty reader before resolver writes. Recognize `ALBUMARTIST`, `ALBUM ARTIST`, `ALBUMARTISTS` and `ALBUM ARTISTS`. Multiple or inconsistent primary claims remain insufficient. Reject leading ID3 and unsupported/rewrite-required layouts; do not expand into another tag-system policy.
- Different individually supported source entity IDs for the same original claim in the supplied trace set make the name-correspondence subfinding insufficient. Preserve each source assertion; do not create aliases or cross-entity equivalence.

Completeness capture and correspondence remain test-only evaluator code. FLAC-only support is deliberate; other formats are insufficient. Before/after raw-capture hashes assume isolated disposable inputs and do not create an atomic transaction across DTO read, hashes and writes. Applicable user decisions and scoped original primary IDs remain unavailable. Homonym handling is limited to available individually supported assertions, not exhaustive discovery.
