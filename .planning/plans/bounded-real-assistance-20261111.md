## Ownership and narrow design

Use the existing coordinator, provider guards, WriteQueue, tag reader and worker persistence. `configure_eval_assistance` continues to accept only disabled or explicit loopback-scripted assistance. `run-rehearsal.cjs` continues to require disabled assistance and zero model allowance. Do not change either ordinary contract to support external endpoints.

The smallest integration is a separate test-only evaluation scope around the existing resolver, with a shared invocation-local budget checked immediately before every OpenRouter wire attempt. Cold and warm share the invocation budget, not already-written media. Schema repair and HTTP retries pass through the same reservation point. No global environment switch, process-wide mutable budget, parallel tagger or new writer is needed.

Rejected alternatives: enabling `live` in the existing evaluator weakens its established safety boundary; a JavaScript proxy that owns real API keys moves credentials out of the native process and cannot by itself account for provider-internal retries or guarantee dollars. A detached manifest checker would be useful preflight but is not a transport-enforced capability and must not be advertised as one.

The new scope is mock-only until a separately reviewed native transport contract supports all requested hard limits. Future activation requires a reviewed manifest digest plus an explicit external approval receipt binding that exact digest and expiry. A JSON `approved: true` written by the runner is not approval. Missing, stale, changed or unsupported approval fails before credential lookup, HTTP client creation or media mutation.

Initial implementation accepts only a mock approval digest supplied separately from the manifest and atomically claims its run ID using exclusive file creation in a retained run directory. A crash permanently consumes that mock approval; there is no allowance reset or resume. Real approval authenticity/trust-root verification is deliberately unsupported, so external execution is unconditionally denied, even if a document claims approval. Concurrent/restarted processes cannot reuse a mock claim directory to multiply its budget.

## Enforceable versus unsupported bounds

The current client records bounded allowlisted attempt diagnostics and uses a shared completion deadline. It retries HTTP failures and may repair malformed JSON, doubling output tokens after length termination. These mechanisms are not a per-run request/token/dollar budget.

The proposed gate must reserve worst-case charges before dispatch, atomically, and retain reservations on errors with unknown usage. Requested `max_tokens` alone does not bound input, reasoning, provider-internal retries, auxiliary charges or actual billing. Actual usage may reconcile a reservation only under a reviewed authoritative contract. Unknown actual usage cannot permit another request. Wall-clock cancellation does not guarantee remote generation or billing stopped.

Bind the final OpenAI-format body after ordinary policy application, not just resolver inputs. Reject fallback/provider-routing metadata, alternate API formats and endpoint changes in the initial scope. Use a scope-local client with proxies and redirects explicitly disabled. Missing model/usage remains unknown; never use the normal response builder's requested-model or zero-usage defaults as accounting facts. Response bytes need a streaming ceiling, not retrospective telemetry.

No current evidence establishes an enforceable provider-side spending ceiling, complete token accounting, stable price contract or model-version pin. Therefore hard dollar and total billed-token bounds are unsupported today, and external execution must remain unavailable. Estimates may be reported separately but cannot satisfy a required hard cap. Do not invent a model or dollar allowance to resolve this.

Catalog genre agreement is not musical genre accuracy. Preserve original/user choices independently from catalog labels; acknowledgment never certifies them. Correct/wrong fills require a scorable source-bound label and observed change; missing means a scorable requested field is absent; retained requires an explicit retention decision and protected prior value; appropriate hold requires an observed hold reason matching an independently specified source/version guard. Unknown decisions, service failures and unscorable fields remain in total requested coverage and are reported separately from the scorable accuracy denominator. Favorable value-level scoring never upgrades the insufficient evidence export.

Keep native provider-first genre, cleanup/local choices, incomplete-discovery versus complete-no-match gates, collaborator and recording/version holds, captured numbering/presentation, selected IDs and content-only ID suppression unchanged.
