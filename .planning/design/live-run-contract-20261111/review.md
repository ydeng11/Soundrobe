### Final resource/stop clarifications and disposition

The security review's next pass raised three medium engineering semantics, not model/user-policy choices:

1. **Storage measurement/admission:** Define logical bytes versus physical disk traffic, repeated fixture deliveries versus unique bodies, registry/WAL attribution, conservative reservations and terminal headroom. Author now specifies single-active-identity registry growth, application/SQLite-VFS write tickets including overwrites and self-bookkeeping, repeated decoded deliveries, and 2-MiB logical / 8-MiB write headroom inside existing caps. Scoped writer/VFS instrumentation or a demonstrated equivalent is a necessary feasibility gate; directory monitoring and current queue guards are insufficient.
2. **Deadline-to-grace ordering:** An admitted blocking write could race terminal publication. Author now revokes admissions, terminates execution groups and confirms quiescence before receipt-only publication, inside the 10-second grace. No intentional postdeadline drain; if quiescence/storage is unconfirmed, retain incomplete membership and unknown writes/usage, block another run and promise no final receipt. No rollback or remote-billing cessation claim.
3. **Supervisor death:** Author now names cross-monitoring broker/supervisor native watchdogs (250-ms heartbeat, 1,000-ms lease) and broker independent deadline checks. The surviving owner closes admission and terminates child groups. Both-owner/host failure, uninterruptible kernel I/O, target-platform termination and stronger containment remain explicit unresolved guarantees, with acceptance blocked where required. No assumed macOS parent-death cleanup.

A narrow final independent security recheck closed all three clarifications substantively at design level. It found one directly introduced summary inconsistency: proposal JSON said quiescence precedes the grace, potentially allowing termination waiting outside ten seconds. The author replaced that sentence with the reviewer's exact requested timing text (and aligned the README): the same ten-second interval includes waiting and receipt-only publication, with no authoritative final receipt if quiescence is unconfirmed. This mechanical wording correction is author-applied; no additional independent whole-document approval is claimed.

The final reviewer explicitly found protocol step 10's admitted-write race compatible with immediate termination: it permits neither draining nor worker reopen/readbacks during grace. Actual writer/VFS coverage (including WAL/checkpoints and self-bookkeeping), pre-I/O bounds, reserved headroom, physical-disk/flush uncertainty and quiescence tests remain unproven. Kill-either-owner, blocked Node/broker async work, lease expiry, terminal state and process-group termination still require offline proof; revocation/termination must not wait on a stalled event loop or indefinitely blocked ledger lock. Heartbeat/lease values are proposed operating parameters, not measured scheduling guarantees. Both-owner loss cannot resume authority or fabricate completion. This final check made no edits or runtime/network/media/private reads and did not treat stale validation as a final seal.
