## Existing guarantees and missing enforcement

- `bounded_eval.rs::Budget::prepare` accepts only `mode=mock`, loopback HTTP and null hard-cost/billed-token contracts. Its caller-supplied digest and exclusive mock claim bind bytes, not authenticated user approval. `infra/mod.rs` exposes it only under `cfg(test)`. Existing ordinary LLM code can call configured endpoints outside this boundary, so no host-wide no-network guarantee is claimed.
- `Budget::authorize/finish/abort_pending` share in-memory reservations within one invocation, bind bodies/roles, stop on unknown usage/model, and do not refund failed dispatches. This does not survive crashes or aggregate different evaluator children. A model echo/diagnostic is not serving-provider or immutable-weight attestation.
- `OpenRouterClient::post_openai` constructs the final body and appends `/chat/completions` to the base URL. Ordinary clients retry HTTP and may repair schema once. `GenreFillResponse` does not receive the model-specific correction policy; the correction policy can enable fallbacks and router metadata. Proposed restrictions therefore need a scoped policy at the final transport, not a blanket claim about current configuration.
- Existing queue integration carries a bounded guard into `mutations.rs::write_track_queued_guarded` (guard at line 803); admitted atomic dispatch may complete after cancellation. Candidate review intent records an obligation, not prior approval. Provider caches and worker writes are separate effects. Model scope is not whole-driver scope.
- Driver publication retains requested membership and provisional scores until gates pass. Inventory preflight is bounded in the mock scope, but native donor/postflight inventories use separate unbounded JSON reads. The driver has per-child watchdogs, not a hard whole-run deadline or a provider-wide admission cap. Its expected four scripted requests would incorrectly reject a legitimate live zero-call hold and cannot be reused unchanged.
- Offline label admission/projection is reviewed and committed. It reports user acceptance separately from catalog agreement and preserves failures/unavailable values. Grounded AI accuracy credit stays zero; no accepted certificate or write authority follows.

The graph query returned obsolete Electron ownership. The inspected Rust/driver files, not that graph, establish this source map. `source-bindings.json` records exact files/ranges and hashes. No public documentation or private account state was newly queried. Historical public URLs/observations in the sealed packet are background, not current verified account/provider enforcement.

## Proposed native boundaries, kept evaluation-only

These are interface responsibilities for later implementation, not new callable APIs in this checkout. Keep `Budget::prepare` and its mock denials intact. Add a separately opt-in ignored evaluation entrypoint only after independent offline validation and explicit implementation authorization. Do not turn a nullable manifest field or environment variable into live authority. Ordinary desktop operation remains unchanged and gains no capability.

1. **Driver plan and isolated preparation.** The maintained driver needs a separate explicit paired plan, arm-qualified job identities, cold-only selection, no minimum-wire assertion, predeclared failure membership, and a native plan-only preparation handoff. Preparation may use authentic loopback fixtures but no model dispatch or candidate application. Fresh synthetic profile materialization would itself require later authorization. Pin its receipts and start counts; do not count preparation as scored outcome evidence. Approval waiting is quiescent: no network or writes while waiting.
2. **Coordinator/client factory.** Keep `fill_genre_if_missing`, `complete_provider_genre`, credit conflict and no-match/version decisions in their existing order. Factor only the existing genre request/client construction enough to capture an eligible final request without dispatch, then replay it under an admitted evaluation capability. The existing nonempty-key configured check needs a deferred native credential capability rather than a fake key in prompts or a global config override. Test that this changes no eligibility decision: configured capability represents an approved configured client, not permission to bypass the genre guards. No response simulation may manufacture the candidate used for approval. A natural hold yields no request to approve.
3. **Native approval/session boundary in `bounded_eval.rs`.** Verify an identity-authenticated receipt outside the untrusted plan against a pre-provisioned trust root, exact signed manifest digest, expiry/revocation, run nonce and resource/privacy/billing terms. An environment-supplied public key or self-authored `approved=true` is not a trust root. Consume approval atomically and durably before credential lookup, model dispatch or final candidate application. The signing identity/provisioning and verifier do not exist today and are implementation/decision blockers, not features inferred from Amp thread permission.
4. **Single shared durable reservation authority.** A native session broker owns one local SQLite journal for the whole run, not each child. Unique run/approval and job-role/body claims, exclusive one-shot consumption, transactionally durable monotonic counters/reservations and terminal stop state precede wire admission. Children receive narrow per-job opaque handles over a protected local channel, not signing authority or resettable limits. Persist and flush the journal/parent directory before acknowledging admission; unsupported durability or unavailable broker denies dispatch. No restart/resume/refund after ambiguous crash: in-flight reservation remains possibly billed and the run becomes terminal. A new child cannot reconstruct fresh counters from manifest JSON. Process concurrency and stale/forged handles must be tested.
5. **Final transport choke point in `openrouter.rs`.** Accept only the broker's admitted request and deferred native credential supplier. Serialize once, bind and send those exact owned bytes. Apply explicit zero retry/repair, one concurrent request, bounded decoded-response reading, cancellation/deadline, exact HTTPS origin/path, no redirects/proxies, no alternative API formats and no model/provider fallback. Scoped errors map to bounded stable allowlisted codes before tracing, events, driver stdout or artifact serialization. Do not reuse ordinary raw `OpenRouterError::Http` display for paid scope.
6. **Provider/ancillary and write boundaries.** `ProviderState` passes a raw `reqwest::Client` to provider clients; `infra/http.rs` only parses retry headers, so it is not a universal admission point. Later code needs an evaluation-scoped admission hook at actual provider sends plus the fixture service's shared ingress count, and must route every inventory path through one bounded reader. Extend existing queue mutation guards with approved destination/candidate/prewrite checks, not another writer. Cache, worker, alias, sidecar and temporary writes need the same run-root policy. No new provider or eligibility adapter is justified.
7. **Projection/publication.** Adapt the maintained `freeze_native_contract/project_native/score`, not a parallel evaluator. `auto_tag_eval.rs` must export explicit evaluation-only phase/arm selection: its present verification and execution both hard-code cold/warm. The scorer also requires cold/warm, identifies jobs without arms and admits only mock manifests. Add cold-only, arm-qualified identities and separately validated live invocation admission without relaxing mock denials. The failure adapter must use frozen requested membership, retain validated available observations and supply unavailable observations for unfinished jobs. Never invent native records or substitute baselines as readback: the current projector requires complete native records and cannot do this unchanged. Add only explicit decision/provenance observations needed to judge provider-first/hold behavior, not guessed reasons from unchanged values. Preserve zero acoustic/grounded credit.

Preparation needs a coordinator-level result before every relevant application branch, including content-only handling: hold/no candidate, provider-only candidate/no request, or eligible candidate/prepared genre request. Each includes job/prewrite identity and actual decision evidence; candidate-bearing variants include the deterministic application template. A request/client hook alone misses early holds and provider-only paths. Keep the existing resolver and guards; no captured request does not mean no candidate. Billie's input `&burn` has only Billie Eilish, while its catalog credit includes Vince Staples: candidate-prescribed collaborator completion is permitted, not blanket baseline equality for artist fields.

Choose an evaluation-only ancillary-stage exclusion before dispatch, explicitly bound into both arms. This excludes album/artist artwork and other ancillary stages while leaving provider matching flags and genre eligibility unchanged. It is an intentional scope difference from whole-coordinator desktop behavior, not an existing guarantee. Existing successful candidate application can invoke artwork resolution with no local art, so stop-on-attempt alone would make the proposed sequence unreliable. Any attempted bypass still denies and terminates; do not tolerate denied ancillary requests to continue. Future offline tests must show the exclusion prevents both album and artist dispatch without suppressing matching or fabricating local artwork.

The proposed ledger lifecycle is preparing, frozen/quiescent, approval-consumed, executing, terminal. The verifier-owned broker creates the preparation identity and authoritative counters before the first counted operation in a fixed ledger registry; callers cannot choose a fresh database. Freeze closes preparation and records a durable checkpoint digest. Approval binds that digest, roots, request/template bytes and remaining global allowances. Attach approval and consume it in one atomic transition with exclusive concurrent consumption; never import/reset counters from caller JSON. Preparation/broker crash makes that identity terminal, with only bounded failure publication allowed. No further preparation after freeze and no resume after consumption. This specifies intended semantics; durability and registry provisioning remain unimplemented feasibility gates.

A non-secret configured-client descriptor must be provisioned separately and bind the approved account/supplier identity without probing credentials or reading user config. The broker alone should hold credentials and own the model socket; reviewed children get authenticated run/job/arm/body/executable-bound handles over a protected channel, never unrestricted keys. Children are trusted reviewed code processing untrusted inputs, not adversarial executables. Descriptor provisioning, channel authentication and credential custody remain implementation gates, not completed mechanisms.

The broker is an enforcement boundary for reviewed evaluation processes and untrusted plans/data, not protection against a malicious OS administrator, same-user process inspection/injection or secret extraction, arbitrary executable replacement, database rollback or direct out-of-band account spending. Protected handles, current-executable hash checking and source bindings reduce accidental/stale bypass; they do not prove a trusted execution environment. If that stronger adversary is required, sandboxing, separate identity/storage or an external authority is a feasibility blocker. No global account guarantee follows from a local ledger.

A requested `data_collection=deny` or `zdr=true` is not verification. If exact policy cannot be satisfied, do not route elsewhere. Scoring runs after output capture in a separate input domain. Compare independently expected full bytes/settings and a native send-boundary receipt, not merely keys, substring bans or a self-reported unchanged flag. Protect source register bytes; source hashes/recording IDs do not authenticate audio. Inferred-unverified review must persist after reopen; packaged highlighting/acknowledgment remains a later UI check, not certified here.

Proposed global limits, not measured feasible or implemented: 512 local provider-send reservations/fixture arrivals across preparation and execution, 32 inventory fetches at 8 MiB decoded per fetch, 16 denied ancillary/unsupported attempts, and 576 total HTTP operations across categories, including denials. Every provider retry consumes the shared category/total budgets even if it never reaches the fixture service; socket/packet counts are not inferred from HTTP arrivals. Allowed live catalog/acoustic/artwork/lyrics/background/tool requests are zero. First unexpected route, external ancillary attempt or fixture miss stops the run; the denial counter is not tolerance for sixteen unauthorized requests. Separate model accounting admits at most the one declared attempt, no retries/repairs, with a 60-second model scope starting at the first paid reservation, a 30-second completion cap and no deadline extension. Both remain clipped to the earlier whole-execution deadline and approval expiry.

Count each admitted HTTP operation once toward the total: provider sends, inventory fetches and the sole model send are disjoint categories; a denied unsupported operation also counts once. Fixture arrival is independent corroboration of a provider operation, not a second charge to the total. Inventory ingress has its own 32 cap and is excluded from the provider-send/arrival cap. Preparation consumes the same category and total counters. The 576 total is an additional ceiling, not a target or sum that permits unclassified calls. Denial terminates on the first violation regardless of unused counters.

The execution's 600-second monotonic whole-driver deadline includes revalidation, materialization, child execution, readbacks, inventories, audit and publication, with subordinate child/Python/inventory deadlines clipped to it. Bounded local preparation is separately capped at 300 seconds and its request/byte counts are signed into the same global budget baseline; counters do not reset after approval or between children. Human approval wait is quiescent and not an execution deadline extension; expired inputs/approval require new preparation/approval. JSON parse, disk/candidate/readback/fixture-body sizes and total storage need explicit finite ceilings calibrated on offline data before implementation acceptance. Those remaining numeric ceilings are null/blocking, not permission for unbounded reads or silently copying the old 128 MiB inventory cap. Deadline expiry cannot roll back an atomic write or cancel remote billing. A finalization grace may write only a bounded failure receipt, never start new model/provider/candidate operations.

An independent native supervisor must own the monotonic deadline, revoke broker admission and terminate driver/child process groups even during synchronous hashing/parsing/disk work. A timer on the blocked Node event loop cannot enforce it. Failure-publication grace needs an explicit finite duration/byte cap before implementation acceptance; it remains unresolved, not an exception for unlimited finalization.

## Failure publication and interpretation

Freeze all six job identities, 72 physical observations, 216 slots, 30 labelable slots and per-arm pairing before any final execution. Keep an atomic durable requested-membership record and initial `incomplete` status. On timeout, crash, cancelled/unknown usage, provider/model mismatch, malformed/oversize response, binding drift, unsupported scope or infrastructure failure, mark unfinished slots unavailable and retain the full denominators. Observed agreement can coexist with failure. Never replace missing readback with a baseline or treat absence of an event as a hold. Missing/damaged final status never means success. Startup recovery can publish retained unknowns but cannot resume a consumed run or refund allowance. Sudden host loss can leave no final receipt; the predeclared manifest is then the denominator source, not a completed experiment.

Write per-job observations/scores as provisional. Authoritative final status is atomically published last after exit, ledger, source, request, payload/readback, review-persistence and projection gates. Report eligibility/call counts, paired user-acceptance differences, catalog agreement, preservation, holds with explicit evidence, failures and unknowns separately. A real output agreeing with the user is not a certificate of source eligibility, musical truth or write safety. Scripted controls and deterministic/provider fills earn no grounded AI credit.
