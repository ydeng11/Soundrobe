# Field-scoped content and performer-credit certificate

Status: independently challenged and revised proposal, 2026-11-09. Ready for review of a non-authorizing evidence-export unit only, not performer-write integration. This proposal issues no certificate and changes no implementation, oracle, acceptance rule, or version guard. All 84 prior source-eligibility findings and the existing exact-edition certificate remain unchanged. No passing native replay is claimed.

## Purpose and chosen boundary

The existing unified coordinator can retain a selected release while finding fuller performer credits elsewhere. A separate certificate would describe why one frozen source supports one mapped credit supplement. It would not declare the donor and selected release equivalent editions.

The proposed first scope is a complete, closed metadata-content package and additive credited-performer fields. Relapse is a worked example, not an identifier exception. The same criteria apply to every artist, release, profile, and cache phase. The certificate is a reviewable evidence record, not a model approval or a new tagging backend.

Three approaches were considered:

- A closed-package, field-scoped certificate is recommended. Every local occurrence and every donor occurrence must be accounted for. This excludes otherwise useful partial donors but makes the first safety contract small enough to audit.
- A per-recording certificate could reuse a credit from a standard album or a larger package. It needs separate rules for partial coverage and cross-package recording variants. Defer it rather than silently using it inside this certificate.
- Broadening the exact-edition certificate or stripping deluxe/version distinctions would merge different claims. Reject this approach. It would also obscure the selected Discogs duration gaps.

The first future integration belongs beside `complete_provider_credits` in `src-tauri/src/commands/auto_tag.rs`, using the same coordinator, provider clients, field decisions, and WriteQueue. The agent may find or interpret evidence and propose a supplement. Deterministic validation owns scope and write authorization. This task does not implement that integration.

## Evidence available before any write

Each decision binds a frozen profile request, not a reconstructed request inferred from successful output. Retain the physical path, immutable input identity, file-set membership, observed duration with units and origin, folder and filename observations, available tags, existing decisions, and a manifest of deliberately withheld evidence. A relative path alone is not proof that a file is unchanged. A changed file, request, decision, source body, or policy revision invalidates the decision and requires revalidation.

The actual native prewrite request and profile baseline define available evidence. The corpus profile arrays describe inputs but do not override native profile clearing:

| Profile | Available local evidence | Not available as independent proof |
| --- | --- | --- |
| `folder_filename` | Folder, filename, physical occurrence, duration, and format that survive in the actual prewrite request. Filename-derived positions must retain that origin. | Captured descriptive tags, numeric tags, and embedded provider IDs. The corpus descriptor retains numeric fields, but native `apply_profile` clears track/disc numbers and totals. Descriptor numbers are not authority to restore those cleared tags. |
| `assisted_without_ids` | Captured tags and the preceding observations, with provider IDs removed. | Stripped IDs or the answer ledger. The word assisted describes existing input tags, not an active model run. |
| `tagged_recovery` | Captured tags and IDs plus the preceding observations. | Treating an existing ID as a verified mapping or a prior assisted tag as acoustic truth. |

Descriptor definitions are visible in `scripts/generate_auto_tag_eval_corpus.py`, `discovery_track`, `assisted_track`, and `recovery_track`. The frozen packet retains those arrays under `cases[].originalProfiles`. Native `src-tauri/src/commands/auto_tag_eval.rs`, `apply_profile`, clears all descriptive and numeric tags for `folder_filename`, clears IDs only for `assisted_without_ids`, and leaves `tagged_recovery` intact. Future replay must bind the actual native prewrite request and profile baseline, because native clearing, generated dummy durations, and request parsing can differ from descriptor fields and original measurements.

Cross-profile evidence is useful for an investigation but cannot authorize a profile's write. A provider independently fetched in that profile may supply an ID as evidence; that is different from importing a stripped embedded ID. An existing selected release or explicit local choice is protected wherever it actually exists in the request or decision store. Do not create Discogs `36441795` in a stripped profile merely because a richer profile contains it.

Captured source-file hashes are inventory claims, not newly verified original audio. Silent dummy hashes bind disposable test inputs only. Neither generated silence, generated tag values, rewritten output, readback, a native accepted candidate, nor a previous certificate is independent evidence of the musical claim being certified.

## Source receipt and certificate contents

Each candidate certificate records the following facts. These are proposed record requirements, not new API types.

- Certificate purpose, policy revision, requested field delta, active profile, file-set digest, and expected old values/decisions.
- Provider, endpoint and request parameters, stable release ID, capture time, HTTP status, raw-body path and SHA-256, and manifest receipt. Record absent provenance as absent rather than inventing it.
- Source-local medium index, release-track UUID or Discogs position plus array index, recording ID when provided, raw titles, album title, disambiguation, video flag, and artist-credit selectors. Distinguish release-track UUIDs from recording IDs.
- For every local physical occurrence, its source occurrence, alternative mappings considered, title and version comparisons, local and provider duration fields with units, deltas, completeness verdict, and rejection or insufficiency reasons.
- Baseline performer identities and display, each proposed addition and its direct credit selector, source disagreements, protected fields, and review state. Provider artist IDs identify evidence entities but are not automatically writable media IDs.
- Separate verdicts for metadata-content compatibility and the requested credit delta. Exact edition, acoustic identity, clean/explicit audio identity, and mastering remain unverified unless separately established outside this certificate.
- The complete bounded-attempt manifest, its digest, and its closure point. Include received sources, failed and unfinished requests, source hashes, pending relevant work, exclusion reasons, and consumed allowances. A timeout closes an attempt operationally but does not turn missing relevant evidence into a completed search.

The source packet is `.amp/in/artifacts/desperado-relapse-independent-review-20261109/source-evidence.json`. Its nineteen source receipts preserve raw fields and capture provenance without native outputs. A matching hash proves which bytes were reviewed, not that a catalog assertion is true. Two credit arrays in one MB response are consistent representations, not two independent sources. Shared catalog data across releases is not independent voting evidence.

## Content, occurrence, version, and duration requirements

A candidate receives a proposed metadata-content-compatible verdict only if all the following requirements hold. Otherwise it is rejected for a demonstrated conflict, or insufficient for missing or ambiguous evidence. Insufficiency is not a verified negative.

1. The album/primary-artist context is supported by profile-visible local observations and the source. A guest occurrence on an unrelated compilation does not establish the album or principal artist. Homonymous artists require source-bound identities or reviewed aliases, not fuzzy name similarity.
2. The donor supplies a complete tracklist within a predeclared whole-package or explicitly selected-medium scope. That scope is fixed before candidate selection. Every local occurrence maps once to one distinct donor occurrence, and every in-scope donor occurrence maps back once. No omitted singles, videos, bonus tracks, or unexplained physical files are allowed. Known duplicates, partial albums, mixed folders, and many-to-one mappings are outside this initial certificate, not silently deduplicated. Provider medium scoping cannot be invented to remove inconvenient extras.
3. Mapping is by physical occurrence, not tag number, provider array order, count, or normalized title alone. Retain medium/position and provider occurrence identifiers. Record all repeated-stem alternatives and why only one remains. Punctuation/case comparison may support uniqueness, but it may not discard instrumental, reprise, remix, live, edit, skit, remaster, mono/stereo, clean/explicit, or other meaningful version evidence. Alias use needs its own source receipt.
4. Both existing track-version and recording-version safeguards must remain satisfied without changing the invocation in the production route under examination. Do not reverse arguments, weaken a predicate, rewrite the local input from the donor, omit contradictory disambiguation, or use this certificate as an override for a failed guard. Store the exact call-site, argument values, source fields, and both outcomes. The diagnostic conventions below do not authorize substituting one route's invocation for another. A new evidence-ingestion requirement must be reviewed separately if the unchanged guards cannot represent the evidence. This proposal claims no new guard pass for Relapse or Desperado.
5. All explicit local and source version claims remain in the evidence, including recording-level disambiguation. A positive contradiction rejects the candidate even when sequence and durations agree. A qualifier missing from one side is not affirmative equivalence. If that absence prevents the unchanged guard or a unique content mapping from being satisfied, the candidate remains insufficient. An unqualified local title cannot be upgraded to an acoustic `explicit` claim because the donor says explicit.
6. Every mapped local occurrence needs a finite positive prewrite duration and a finite positive provider release-track duration. Convert units from the documented source schema, not magnitude guessing. The proposed default bound reuses the existing matcher rule, absolute difference at most `max(5 seconds, 3% of local seconds)`. This is a metadata comparison bound, not an acoustic identity threshold. It is a proposed reused limit, not a calibrated confidence level. All nested recording lengths, when present, must also be finite, positive, retained, and within that same bound of the local measurement. Conflicting lengths cannot be resolved by choosing the convenient level. Missing release-track duration is insufficient for this initial certificate, even when another release has a suitable value. Duration agreement never resolves a title/version contradiction or a nonunique mapping.
7. Album title, source disambiguation, and full bonus content are evaluated together. A title without `(Deluxe)` can describe deluxe content when another raw field explicitly says deluxe and the complete mapped content agrees. A label alone, a matching count, or a common record label cannot establish that conclusion. Incompatible bonus recordings reject the package. A larger package containing the same recordings is outside the closed scope. Do not normalize away edition labels and then call the normalized result evidence.

These requirements concern catalog metadata only. They do not authenticate local sound, encoding ancestry, pressing, edition date/country, barcode, catalog number, mastering, or whether the local audio is clean or explicit. A catalog recording ID is not a fingerprint observation. Catalog sequence/title/duration support, guard results, field applicability, and final authorization are separate reported facts.

### Qualifier observations do not inherit a guard's boolean

The proposed read-only exporter records local title, filename, source track title, source recording title/disambiguation, and release context before comparing them. For a local observation `L`, its filename `F`, the unmodified parsed source track `R`, raw recording title `RT`, and raw recording disambiguation `RD`, named local-to-source diagnostics are `track_versions_compatible(L, F, R)` and `recording_versions_compatible(L, RT, RD)`. Retain raw fields that `R` does not represent. Missing recording detail is reported as unavailable, not invented from the release title.

Those named diagnostics are not the existing genre-donor route. That route currently uses `track_versions_compatible(R, "", L)` and `recording_versions_compatible(R, local_title_or_filename, None)` in `complete_provider_genre`. Export that actual invocation separately whenever that route is examined. Do not choose the direction with the favorable result. Current `versions_compatible_with_disambiguation` can return early when titles compare successfully, so even a passing diagnostic does not prove that raw recording disambiguation was adjudicated.

The initial proposal uses the following conservative field-applicability table. The exporter itself authorizes no delta in any row.

| Raw qualifier observation | Required guard report | Requested-field applicability | Candidate decision for a later authorizer |
| --- | --- | --- | --- |
| Neither side asserts a meaningful variant; no conflicting profile-visible context exists | Exact unchanged route arguments/results plus the named diagnostics | No marked-variant obstacle to metadata applicability, subject to all other evidence requirements. Acoustic identity remains unverified. | May continue to other checks; not automatic acceptance. |
| Both sides have matching source-bound variant claims | Same reports, with the supporting raw selectors | Established only at the metadata-claim level, not acoustic proof | May continue if every applicable unchanged guard passes. |
| Explicit contradiction, such as local Clean versus source explicit | Report the contradiction even if a guard returns true | Contradicted | Reject the candidate. Zero authorized delta. |
| One side has a meaningful qualifier and the other does not, or relevant context is unavailable | Report absence separately from a false guard or contradiction | Unresolved in this first scope | Insufficient. Zero authorized delta even if an unchanged guard passes. No assumption that guest credits are invariant across variants. |
| A guard fails despite otherwise matching metadata, or an observation cannot be represented | Record the exact failed/unsupported comparison | Unresolved or contradicted according to raw evidence | No delta. Preserve the failure; request separately reviewed evidence handling rather than override it. |

This makes Relapse's track-13 addition insufficient under the initial proposal: M says explicit and the local profile does not establish that variant. The correct bonus/content sequence and direct Dr. Dre credit remain supported catalog observations. Desperado's filename-only missing instrumental qualifier is separately insufficient. What non-acoustic evidence could resolve variant applicability is an open policy question, not a hidden implementation choice.

## Exact performer fields and conflict policy

The writable whitelist proposed here is per-file `artist` and `artists`, only as a consistent pair representing the existing credited-performer display and list. No title suffix, album artist, composer, producer, instrumentalist role, genre, year, album display, track/disc position or total, cover, lyrics, release ID, recording ID, artist ID, format, country, barcode, or mastering field receives authority from this certificate.

A source must directly credit the mapped occurrence. For MB, retain release-track `artist-credit` and nested recording `artist-credit`; in this initial scope both must exist and agree on credited identities and explicit featuring relationships. Whitespace/case changes within the same joinphrase and punctuation-only co-billing separators can compare without creating a new role. Co-billing punctuation versus explicit `feat.` is missing relationship agreement, not cosmetic equivalence or an incompatible identity set. Such a difference is insufficient for a new supplement in this first scope. An explicitly contradictory relationship is a conflict. All raw joinphrases remain recorded, and no existing equal-set display is rewritten.

For Discogs, use explicit mapped track `artists` and track `Featuring` entries. If track `artists` is absent, this initial certificate does not construct a complete donor performer set by inheriting the album artist. Record that set as insufficient while retaining each direct `Featuring` assertion as individual guest evidence. Omission is not an empty set or a denial of the principal artist. Existing selected/local baseline credits remain preserved by their own authority. Various Artists and other compilation album credits never replace explicit track principals. Album-wide `extraartists`, producer relations, biographies, and reputation cannot create an addition. Other role vocabularies remain insufficient until separately reviewed.

Compare performer identities using provider IDs within the same namespace or a source-bound reviewed cross-provider/name correspondence. Exact normalized display names can support an unambiguous identity but cannot merge homonyms or invent an alias. Ambiguous splitting of a band name or joinphrase holds the field.

The baseline includes the local and selected-provider collaborators that the existing authority policy preserves. The proposal does not relabel every nonempty tag as trusted. Conflicting baseline credits are held for review, not resolved by selecting whichever produces a nested set. Explicit user locks, prior rejections, and cleanup decisions take precedence. A local omission without an explicit completeness assertion is not an exclusion of a guest. A user decision to keep a particular complete credit is different and blocks automatic supplementation.

The credit decision uses these observable rules:

- If baseline and donor identify the same performer set, retain the current presentation byte-for-byte where possible. A different ordering or joinphrase does not justify a write.
- If the donor is a strict superset of a compatible, nonempty baseline, each extra identity has direct mapped evidence, and no protected decision conflicts, propose only the additions. Preserve every baseline collaborator and its relative display/list order. Add the missing credited name using source-supported spelling and a presentation that does not invent a role. If display/list consistency requires changing a protected presentation, hold rather than silently rewrite it.
- If the donor is a subset, preserve the baseline and do not delete anyone. Missing source credits are not evidence of absence. Record no addition.
- If baseline and donor are non-nested, reject the supplement and hold the affected occurrence. Never union guest assertions such as `{Eminem, Dr. Dre}` and `{Eminem, 50 Cent}` into a manufactured complete credit. This is a conflict, not a majority vote.
- Consider all otherwise eligible evidence received in the bounded attempt before deciding. If two proposed superset donors disagree non-nestedly, hold even when each separately extends the baseline. Evidence order and cache order cannot select the winner. An explicit source statement denying a performer or disagreeing on the credited role is also a conflict, even if sets appear nested.
- If the baseline primary credit is missing, identities are ambiguous, the source credit is absent, or version applicability is unresolved, this supplement certificate is insufficient. Existing missing-primary recovery remains a separate decision within the same workflow.

### Authorization donors and conflict evidence have different scopes

Authorization donors satisfy the complete-package requirements and the field requirements above. Conflict evidence cannot authorize a supplement. It can come from an otherwise excluded package only when the particular local occurrence has an unambiguous source-bound title/artist/identity mapping, positive finite durations within the stated bound, and established variant applicability under the qualifier table. It must directly assert a performer or relationship for that occurrence. Full-package coverage is not required to hold a contradiction against a mapped field.

A non-nested direct credit or explicit performer/relationship denial in that conflict-evidence set holds the affected field, even when the same source is excluded as an authorization donor. An excluded source with a plausible occurrence link but unresolved mapping, variant, or relationship is recorded as unresolved relevant evidence and also prevents finalizing that supplement until resolved or explicitly excluded with source-backed reasons. A demonstrated unrelated occurrence, such as Smack That, is excluded without that veto. Mere search ranking, a guest name elsewhere, or model plausibility does not make evidence relevant.

The bounded attempt closes against a frozen manifest before a decision is finalized. Evaluate all donors and conflict evidence once against the original baseline, not a progressively expanded credit. Unfinished relevant requests or unresolved relevant assertions yield insufficient, zero delta. Failed unrelated work need not block independently supported fields. Newly received relevant evidence or a changed source/decision/file invalidates the old decision revision and requires revalidation before a write. A later contradiction after a completed write creates a new held review revision through the existing workflow, not silent removal of a collaborator.

An unsafe package is excluded from authorization, not mislabeled as disproving every contained credit. Standard Discogs 2058854 and the larger/wrong-bonus MB packages genuinely corroborate Dr. Dre here; they do not contain the constructed incompatible-guest observation. Their received assertions remain in the manifest with their scope and relationship/variant limits. A new conflict is never discarded solely because its package cannot authorize a write.

Source provenance and assistance involvement remain distinct. A directly mapped provider addition is provider-origin evidence, even if an agent found it. A semantic link derived by an agent remains assisted and requires the existing review obligation and visible uncertainty. Persist the proposed delta, sources, conflicts, and obligation before any future write. Acknowledgment does not verify the evidence. If required per-field provenance/highlighting cannot be represented, do not count the fill as useful completed tagging. Preserve unrelated supported fields when a credit is held, subject to the existing coordinator's atomic-write safety rules.
