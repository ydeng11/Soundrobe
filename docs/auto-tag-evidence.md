# Auto-tag evidence and recovery

Monitoring's run history includes **Show evidence** for each album. New runs retain provider attempts, candidate rejections, per-file recording scores, effective nonsecret configuration and file-versus-release coverage in the worker database. Older runs show that evidence was not retained; the application does not reconstruct historical reasons from current tags.

A successful file write does not prove a complete album. Partial collections and unresolved editions remain in review. Strong recording recognition writes only verified title, credits and recording identity; unresolved album, year, release IDs and positions remain unchanged. A consensus across fully examined editions may support common album fields. Clear-tag settings do not clear unresolved fields in these partial writes. Named remixes, live performances, demos, instrumental/acapella recordings, and clean/explicit versions remain distinct.

New AcoustID evidence retains up to 16 recording alternatives per file, including result/recording/release IDs, scores, durations, authoritative title/credits/disambiguation, and decision reasons. At most four plausible recording identities per file and 32 uncached recording details per folder are examined in one pass. A duration contradiction can eliminate a candidate; an unavailable detail or an unidentified high-scoring cluster cannot. A same-provider HTTP redirect can establish a canonical recording alias; an unexpected ID in a response body cannot. Existing tags do not break a genuine recording tie.

MusicBrainz disambiguation can establish a live performance or named remix even when the canonical title omits the qualifier. The qualifier must actually be supported; another remix or a studio recording does not qualify. Canonical titles retain the supported version wording from tags or filenames.

Duplicate titles do not establish duplicate audio. Release matching can group compatible recording IDs only with matching acoustic evidence and duration, and expands the mapping back onto every physical file. Long-file duplicates require full-duration raw fingerprints; a matching 120-second prefix is insufficient. Approximate comparisons require informative fingerprints, near-complete overlap and both whole-file and local-window agreement. All members of a duplicate group must agree pairwise. Failures stay within that recording group. It never deletes or moves copies.

Temporary transport, HTTP 429 and HTTP 503 failures schedule only affected albums. The worker retains due times and the originating run across restart. Automatic retries are limited to three deferred attempts, with exponential backoff and per-folder jitter; provider `Retry-After` deadlines are never shortened. Existing catalog/detail caches preserve completed discovery work, and cached details do not consume the next network budget. Budget-limited discovery, conflicting identities and ambiguous editions require evidence/review rather than automatic outage retries.

Edition discovery checks at most eight uncached release details per pass. Raw provider details are saved in the existing cache and are reevaluated against current local evidence on every explicit retry; accepted matches are never cached by this path. The evidence lists unexamined editions. A unique pressing or unanimous album fields cannot be accepted while competing editions remain unexamined. More than 100 nested AcoustID memberships are bounded and marked incomplete: recording fields can still be verified independently, but the truncated membership set cannot establish an edition or album consensus.

Monitoring's **Complete folders** count uses the existing strict completion policy. Its separate file summary counts physical files considered/written and folders with writes; verified title/artist, album and edition fields are separate measures. Provider verification excludes AI proposals. New run summaries survive ledger truncation; complete older ledgers can show file counts, while missing provider-verification evidence remains unknown. These measures do not turn preserved local tags into verified values or silently approve a personal collection's grouping.

The completion target is an accounted-for title, track credit, version and approved album grouping for every physical file. Optional pressing IDs are audited separately. Genuinely ambiguous identities and unapproved local grouping still require review; lowering confidence thresholds or treating present tags as correct cannot establish 100% accurate completion.

An HTTP 402 response opens the run's durable AI circuit. Subsequent tagging and genre AI requests in that run and its automatic retry lineage stop; provider recognition continues. Check service credits/settings before choosing an explicit retry. An explicit operator retry starts a new run and resets the deferred-attempt budget; it is the deliberate point at which AI may be tried again.

Configuration evidence records enabled/configured flags, the effective model and relevant behavior settings. Keys and endpoint URLs are neither stored nor hashed into the fingerprint. SQLite additions preserve existing worker rows and review flags. Evidence and terminal worker status commit together; failure to save diagnostics is surfaced as a failure rather than a healthy result.

The committed 66-folder/453-file manifest is a post-run structural regression fixture, not an identity oracle. Network-free copied-media safety checks establish preservation and repeat-run stability. Recognition correctness uses independently specified mocked provider identities; live recognition coverage requires a separately authorized provider run.
