# Security policy

## Supported versions

Soundrobe is under active development. Security fixes are applied to the
current default branch and the most recent published release when practical.
Older development snapshots may not receive a fix.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability.

Use GitHub's private vulnerability reporting or security advisory workflow:

<https://github.com/ydeng11/Soundrobe/security/advisories/new>

If private reporting is not available for the repository, contact the
repository owner privately through GitHub before disclosing the issue publicly:

<https://github.com/ydeng11>

Include only the information needed to reproduce the issue:

- affected Soundrobe version or commit;
- operating system and deployment context;
- a minimal reproduction or proof of concept;
- the potential impact; and
- any suggested mitigation.

Please redact API keys, credentials, private media paths, personal data, and
unrelated logs. If the report involves a provider token or another secret,
revoke or rotate that secret immediately.

## What to expect

The maintainer will acknowledge a report when it is received, investigate the
impact and affected code path, and coordinate a fix or mitigation. Please
allow reasonable time for triage before public disclosure.

Security reports are handled privately. Public issues may be closed or
redirected if they contain sensitive vulnerability details.
